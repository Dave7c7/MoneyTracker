2026-10-21 | ESLint 9 flat config with `eslint-config-next` | Next 16 ships flat configs; ESLint 9 is the version the Next plugin set is tested against.
2026-10-21 | pnpm with `node-linker=hoisted` | Next.js "standalone" output only resolves its dependencies from a flat `node_modules`.
2026-10-21 | The sync service lives in `packages/db` | It is the only layer allowed to write to the database, and it consumes adapters through the adapter interface.
2026-10-21 | Phase 1 categories come from the bank-category mapping table | The dashboards need categories before the review inbox exists in Phase 2; the mapping table is a real, seeded user table.
2026-10-21 | Transfers are excluded from spending by category kind, not by detection | Transfer detection is Phase 3; excluding by kind keeps the dashboards correct now and unchanged later.
2026-10-21 | Balances are monthly snapshots, never summed from transactions | Required by `rules/data-and-money.md`, and it matches how statements actually work.
2026-10-21 | Review threshold is configurable, default 0.8 | Bank categories are capped at 0.7, so the default sends them to review; the threshold is configurable per the rules.
2026-10-21 | No Playwright end-to-end tests yet | The e2e flows listed in `rules/testing.md` belong to Phase 2 and Phase 3; Phase 1 is covered by unit, contract and database tests.
2026-10-21 | Demo data is anchored to a fixed date (2026-10-15) | A fixed anchor keeps the seeded dataset and its tests reproducible.
2026-10-21 | Icons are generated by a script instead of committed binaries | The brand colour stays in one place and the repository stays text-only.
2026-10-21 | `docker compose up` starts an empty app; the demo dataset is a profile | Matches the Phase 0 "Done when" checklist and keeps production installs free of demo data.
2026-10-21 | A rule change re-categorizes every unlocked transaction, not only the matched ones | The pipeline is pure and cheap, and it makes deleting a rule put the data back exactly as it was.
2026-10-21 | The review inbox groups by merchant, not by transaction | The rules ask for one decision to clear many; a merchant is the unit a person thinks in.
2026-10-21 | Confirming an item in the inbox locks it as a manual edit | `rules/categorization.md` says a cleared item is locked, so the decision survives the next sync.
2026-10-21 | Undo restores the whole assignment, not just the category | An undo that leaves the source and the lock changed is not an undo.
2026-10-21 | Bulk edits and rule creation are undone through the server | The client cannot know what the previous assignment was, and the server is the only place that can put it back.
2026-10-21 | The bottom navigation has five tabs; accounts and rules live one tap away | Seven tabs do not fit a 360 pixel phone, and rules and accounts are set up once rather than checked daily.
2026-10-21 | The end-to-end tests run against their own database, reset before every run | They change data, and a test must never depend on what a previous run left behind.
2026-10-21 | The database tests run in their own Vitest project, one file at a time | They share one scratch database, so two files must not truncate it at the same time.
2026-10-21 | The client list of transactions is remounted when the filters change | A client component keeps the rows it was given, so without a new key the list would show stale rows after a filter change.
2026-10-21 | Browser-side settings live in `lib/settings.ts`, not in the environment module | A client component that imports the environment module drags the database driver into the browser bundle.
2026-10-21 | CSV import is the guaranteed data path; a live provider is an optional upgrade | The export format is not known yet, so the baseline must not assume the columns of one institution.
2026-10-21 | The CSV adapter is generic: column mappings are saved as named profiles per institution | Any bank's export must be importable without new code; SoFi is one profile, not a special case.
2026-10-21 | The live provider is chosen by a trial, not by assumption | SimpleFIN, Teller, Plaid and the SoFi export all work in theory; coverage, price and terms are unverified.
2026-10-21 | One provider per account, many providers per install | Coverage differs per bank, so the app must not depend on a single aggregator.
2026-10-21 | Each source declares its own history window and refresh cadence | SimpleFIN refreshes about daily and may hold under 90 days; a CSV export reaches two years back.
2026-10-21 | The first import is a CSV, so that history no provider can backfill is not lost | Only an export carries the past; an aggregator only carries what it can see from today.
2026-10-21 | When a provider covers an account already imported by CSV, the provider becomes authoritative and the imported rows are relinked | One bank account must not appear twice because it was imported twice.
2026-10-21 | A category supplied by a provider counts as bank-provided, capped at 0.7 confidence | A provider's own category is not an explanation the user can trust blindly, exactly like a bank's own category.
2026-10-21 | Continuous integration runs the unit, lint, typecheck and end-to-end suites on every push | The suites pass locally; CI keeps them honest.
2026-10-21 | The end-to-end suite uses its own database in CI as well | The tests change data, so a shared database would make one run depend on another.
2026-10-21 | Playwright writes an HTML report when the CI environment variable is set | The report is what makes a failed CI run readable without downloading logs.
2026-10-21 | The end-to-end readiness probe is the health check, not the home page | Playwright starts the web server before the global setup creates the schema, so the probe must not need a table.
2026-10-21 | `apps/web/next-env.d.ts` is excluded from formatting | Next regenerates the file, so formatting it only adds noise to every diff.
2026-10-22 | A transfer needs two accounts, equal and opposite amounts, postings within three days, and a specific word on one side | The rules ask for opposite amounts and close dates; the word ("transfer", "credit card", "thank you", "payment received") keeps a refund or a bill from looking like a transfer.
2026-10-22 | A refund is never a transfer, even when it matches an outgoing payment | A merchant giving money back is not money moving between accounts.
2026-10-22 | The word "autopay" alone does not make a transfer | A phone bill paid by autopay is spending, and treating it as a transfer would hide it from the totals.
2026-10-21 | A confirmed transfer is an assignment with the source `transfer_detection` and confidence 0.95 | Every assignment has to be explainable, and this one says exactly why.
2026-10-21 | A suspected transfer keeps the transfer category but a low confidence | It must never count as spending, and it still has to be looked at.
2026-10-21 | Changing a category by hand takes a transaction out of its transfer group | A decision the user made beats the detection.
2026-10-21 | Choosing the `Transfer` category by hand keeps the transaction in its group | Saying "this is a transfer" should not throw the link away, and it confirms a suspected one.
2026-10-21 | Transfer detection runs after every import, because both sides have to be in the database first | The matcher needs two transactions before it can pair them.
2026-10-21 | The transfer step sits between merchant memory and the bank category | A detected transfer is more reliable than a bank's own category, and a user rule still beats it.
2026-10-22 | The end-to-end tests build the app and start it on port 3100 | A development server watches the repository and reloads whenever a file changes, which reloads the browser mid-test and disturbs a running development server.
2026-10-22 | The end-to-end build goes into its own directory | The tests and a development server must never write to the same build directory.
2026-10-22 | The web scripts take their port from the environment | The end-to-end tests need their own port, and the container sets `PORT` as well.
2026-10-22 | The page says when its scripts did not load | The numbers come from the server and the charts from the browser, so a page without scripts looks broken without saying why.
2026-10-22 | The charts fall back to the numbers when there is no JavaScript | A browser without scripts should still be able to read the month.
2026-10-22 | A CSV row is identified by the account, the date, the amount and the description | Importing the same file twice must update the rows it already has, not make new ones.
2026-10-22 | Two rows that look exactly the same in a file stay two rows | Two coffees on the same day are two coffees; a number keeps them apart while the import stays repeatable.
2026-10-22 | A mapping profile is saved before the preview | The ids of the rows come from the profile, so the preview and the import can only agree when both use the same one.
2026-10-22 | A profile keeps the key of its account even when it is renamed | Renaming a profile must never move its history to another account.
2026-10-22 | A split lives next to the transaction, not in it | The row the bank gave us keeps its amount, its date and its description; only the parts are the user's.
2026-10-22 | The parts of a split always add up to the whole | A split that does not add up is a rounding mistake waiting to happen, so it is never saved.
2026-10-22 | A split transaction is locked, like a manual edit | The user decided how the money is split, so no rule and no later import may move it.
2026-10-22 | A transfer cannot be split | Money that moves between your own accounts is not spending, so it has no parts.
2026-10-22 | The dashboards count the parts, not the whole | A hotel bill that is also dinner is groceries for one part and restaurants for the other.

2026-10-22 | The end-to-end tests check that the app booted and that a chart drew a bar | A page without scripts and a chart without bars both look like a working page, so the tests have to look at the pixels.
2026-10-22 | A recurring charge needs three charges of the same merchant, within ten percent, on a regular cadence | The rules ask for three occurrences and a regular rhythm; the amount window keeps a shop that one day charges twice out of it.

2026-10-22 | A dismissed recurring charge is never detected again | The user's decision is final, exactly like a manual categorization.
2026-10-22 | A budget rollover carries one month of what was left over | Carrying every empty month would multiply the limit; a rollover means last month's leftover.
